\begin{abstract}
Coding assistants that operate on proprietary or regulated source code cannot
transmit that code to a hosted model, which forces deployment onto local
open-weight models. Such models are substantially less reliable than frontier
models at structured tool invocation: they emit malformed call headers,
mis-named arguments, and invocations written as prose rather than as calls.
Production agents absorb these failures with tolerant parsers and recovery
heuristics. This paper shows that those heuristics carry an unmeasured security
cost. We formalise the \emph{dispatch surface} of an agent as the set of text
regions from which its orchestrator can derive a tool invocation, and show that
recovering invocations from model prose transitively admits repository contents
and command output, because agents routinely restate what they read. On an
injection suite of \PH{N} scenarios, enabling prose-level recovery raises
indirect-prompt-injection success from \PH{A}\% to \PH{B}\%. We then show the
repair is avoidable. The Harmony response format separates free-form reasoning
from a rigid call header and argument body, so a grammar may be applied to the
machine-parsed regions alone. Channel-scoped constrained decoding activates only
after the model has committed to a call and constrains each invocation against
its own tool schema, eliminating structural failures from a baseline rate of
\PH{C}\% without the tool-call suppression reported for whole-completion
constraints. Compiling the permission model into an operating-system-enforced
capability profile reduces attack success to \PH{D}\% at \PH{E} cost in task
success. Experiments use gpt-oss-20b on a single GPU, fully offline, with
seed-locked reliability@5.
\end{abstract}

\section{Introduction}

Large language model agents now perform repository-scale software engineering
tasks by reasoning, invoking tools, observing results, and repeating until the
task is discharged~\cite{yao2023react,yang2024sweagent}. The capable instances
of this pattern are hosted services, and using them requires transmitting source
code to a third party. For regulated, classified, or commercially sensitive
codebases that requirement is disqualifying, which leaves only local
open-weight models executing on infrastructure the organisation controls.

Local deployment introduces a reliability problem. A model in the twenty-billion
parameter class is markedly weaker than a frontier model at the one capability
an agent depends on absolutely: emitting a syntactically valid tool invocation.
In our own deployment we observe duplicated recipients in call headers, argument
objects that use a parameter name belonging to a different tool, and calls
written as prose inside the reasoning channel with no header at all. Contemporary
agent implementations absorb such failures through tolerant parsing: a strict
parse is attempted, and on failure a permissive parser reconstructs whatever it
can, including reconstructing an invocation from ordinary prose.

This paper argues that such repair is both unnecessary and unsafe, and
substantiates each half of that claim.

The safety half proceeds from a definition. We call the \emph{dispatch surface}
of an agent the set of text regions from which its orchestrator can derive a
tool invocation. Under strict parsing this surface contains only well-formed
call headers in model output. Once prose-level recovery is enabled the surface
expands to all prose the model emits, and because an agent that reads a file
routinely restates its contents while reasoning, the surface transitively
contains repository file contents and command output. Those are attacker-
controlled in any realistic setting. A repair mechanism introduced to raise
task success therefore constructs a path from untrusted input to tool execution.

The necessity half proceeds from an observation about the response format. The
Harmony format used by gpt-oss~\cite{openai2025gptoss} partitions assistant
output into named channels, and a tool call consists of two syntactically rigid
regions, a header and a JSON argument body, surrounding and following a region
of free-form reasoning. Every structural failure we observe occurs in the rigid
regions and none in the free one. A constraint therefore does not need to apply
to the whole completion. Applying it to the rigid regions alone avoids the two
costs reported for whole-completion constrained decoding, namely degradation of
reasoning quality and outright suppression of tool calling in open-weight
models~\cite{constrainttax2026,structfail2026}.

We make four contributions.

\begin{itemize}
\item A fully offline code agent in which the Harmony prompt is rendered and
parsed client-side over raw token identifiers, which is the property that makes
token-level intervention possible (Section~\ref{sec:arch}).
\item \emph{Channel-scoped constrained decoding} (CSCD), a decoding procedure
that constrains only the machine-parsed regions of a completion and validates
arguments against the schema of the specific tool invoked
(Section~\ref{sec:cscd}).
\item A formalisation of the dispatch surface, a measurement of the
reliability--security trade-off it induces, and a capability profile that
enforces the permission model below the agent process
(Section~\ref{sec:surface}).
\item An evaluation protocol with objective grounding verification and
seed-locked reliability@$k$ reporting (Section~\ref{sec:eval}).
\end{itemize}

\section{Related Work}

\textbf{Agentic coding.} The reason--act--observe loop originates with
ReAct~\cite{yao2023react}; SWE-bench established repository-scale issue
resolution as the standard task~\cite{jimenez2023swebench}, and SWE-agent showed
that the design of the agent--computer interface, rather than model scale alone,
governs success~\cite{yang2024sweagent}. CodeAct argues for expressing actions
as executable code~\cite{wang2024codeact}. We adopt the single-agent loop and the
interface-design emphasis, and depart from this line by treating the orchestrator's
parsing behaviour as a security-relevant component rather than an implementation
detail.

\textbf{Constrained decoding.} Grammar- and schema-constrained decoding
guarantees that generated output conforms to a formal
language. Recent work reports that constraints eliminate structural failures in
small models while leaving a scale-dependent semantic gap~\cite{structfail2026},
that open-weight models incur a measurable ``constraint tax'' and can cease
calling tools altogether when a compiled automaton renders the call-opening
token unreachable~\cite{constrainttax2026}, and that constrained decoding
functions as repair rather than improvement in tool-call
abstention~\cite{repairnot2026}. Our contribution is orthogonal to the choice of
grammar engine: we change \emph{where} the constraint applies, exploiting the
channel structure of the response format to exclude the reasoning region, which
is precisely the region the reported costs are attributed to.

\textbf{Agent security.} Indirect prompt injection against tool-using agents has
been benchmarked in realistic deployments~\cite{livepi2026,gitinject2026}, and
policy-graded evaluation of coding agents in hardened environments has been
proposed~\cite{permdenied2026}, as has deterministic authorisation prior to tool
invocation~\cite{beforetool2026}. A recent survey of execution security for
coding agents catalogues isolation, access-control, and time-of-check-to-time-of-use
weaknesses~\cite{balkan2026}. These works evaluate defences against a fixed agent.
We instead show that a widely deployed \emph{reliability} mechanism enlarges the
attack surface, and we quantify the resulting trade-off.

\textbf{Context management.} Compaction is standard for long-horizon agents, and
it has been shown to erase in-context safety constraints
silently~\cite{govdecay2026}. Our evidence ledger is designed to be immune to
compaction for exactly this reason.

\section{System Architecture}
\label{sec:arch}

\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth]{figures/fig1-system.png}
\caption{Architecture of the proposed agent. The turn state machine drives a
model path (client-side Harmony rendering over raw token identifiers) and a tool
path (three tool tiers behind the permission engine and an enforced capability
profile). Shaded components are introduced in this work. All components execute
on a single host with no network egress.}
\label{fig:system}
\end{figure}

Fig.~\ref{fig:system} shows the architecture. Every component executes on one
host. No component contacts a network service, and the agent requires no
embedding model, vector store, or precomputed index.

\textbf{Deployment setting and threat model.} The user and the shell they already
possess are trusted. Repository file contents, command output, dependency
metadata, and filenames are \emph{untrusted}: an attacker who can contribute to a
repository, or influence the output of a build or test command, controls them.
A malicious model, a compromised inference server, and hardware attacks are out
of scope. We note one limitation of the present implementation: the inference
client reaches the model server over unauthenticated HTTP, which is sound for a
loopback deployment and is not sound if the server is placed on a separate host.

\textbf{Client-side Harmony.} The codec renders the conversation directly to
token identifiers and parses returned token identifiers back into channels, so
no server-side chat template intervenes. This is presented as an enabling
decision rather than an implementation preference: it is the reason a
mid-completion hand-off to a constrained decode is available at all, and a client
communicating through a chat-completions abstraction cannot perform the procedure
of Section~\ref{sec:cscd}.

\textbf{Turn orchestration.} A state machine drives one user turn. Recovery
behaviours are expressed as independent policy objects, so an experimental
configuration is a subset of enabled policies rather than a code variant. This
matters methodologically: the ablation in Section~\ref{sec:eval} is a
configuration, not a fork.

\textbf{Tool tiers.} Tools are organised as a funnel that navigates the
repository rather than indexing it: \texttt{list\_dir} and \texttt{glob} to
locate files, \texttt{grep} to locate symbols within them, and \texttt{read} to
retrieve specific line ranges. An execution tier provides a persistent shell, and
a write tier provides read-before-write, atomic, reversible edits.

\textbf{Governance.} Policy and enforcement are separated. The permission engine
resolves each mutating invocation through path-scoped allow, ask, and deny rules
under one of five session modes, failing closed. The capability profile then
enforces the resulting decision below the agent process, as described in
Section~\ref{sec:surface}.

\textbf{Instrumentation.} An evidence ledger, a JSON Lines trace, and a per-run
manifest record every decision and observation. Every quantity reported in this
paper derives from a committed trace file.

\section{Channel-Scoped Constrained Decoding}
\label{sec:cscd}

\begin{figure*}[t]
\centering
\includegraphics[width=0.92\textwidth]{figures/fig2-cscd.png}
\caption{Channel-scoped constrained decoding. Phase~A decodes unconstrained; on
detecting a commentary-channel onset, Phase~B selects a recipient from the tool
registry, the canonical header is emitted by the orchestrator rather than the
model (dark region), and Phase~C decodes the argument body under the JSON schema
of that specific tool. The grammar is inactive over the reasoning channel, so the
constraint can neither tax reasoning nor suppress invocation.}
\label{fig:cscd}
\end{figure*}

\subsection{The structure the method exploits}

A Harmony tool call has the form
\hmtok{channel}\texttt{commentary to=functions.read}
\hmtok{constrain}\texttt{json}\hmtok{message}\texttt{\{\ldots\}}\hmtok{call},
preceded by a reasoning message on the \texttt{analysis} channel. The header and
the argument body are rigid; the reasoning is free. Table~\ref{tab:failures}
classifies the structural failures observed in our deployment, and every one of
them falls in a rigid region.

\subsection{The procedure}

Fig.~\ref{fig:cscd} shows one assistant completion under CSCD. The decode
proceeds in phases over a single token stream, with the key-value cache retained
across phase boundaries.

\emph{Phase~A.} Decode without constraint. An incremental recognizer consumes the
token stream and terminates the phase on one of two conditions: completion of a
message on the \texttt{final} channel, which ends the turn, or detection of a
commentary-channel onset, which indicates that a tool call has begun.

\emph{Phase~B.} Decode the recipient under a grammar admitting exactly the names
in the tool registry. The model has already selected a tool semantically; the
grammar governs only its spelling.

\emph{Phase~B$'$.} The orchestrator emits the canonical header token sequence
itself. The model does not generate the header, so a malformed header is not
improbable but unreachable.

\emph{Phase~C.} Decode the argument body under the JSON schema of the selected
tool, terminating at \hmtok{call}.

\subsection{Why the reported costs do not apply}

\textbf{No constraint tax on reasoning.} The grammar is inactive throughout the
reasoning channel, by construction rather than by tuning. The reasoning token
distribution is therefore unmodified, and we verify this empirically through the
reasoning-quality delta of Section~\ref{sec:eval} rather than asserting it.

\textbf{Suppression is structurally impossible.} The failure reported for
whole-completion schema constraints is that the compiled automaton forbids the
token opening a tool call, so the model ceases to call tools~\cite{constrainttax2026}.
CSCD activates only after the model has already begun a call, so this mode cannot
arise. We nonetheless report tool-call rate per task as a detector.

\textbf{Tighter than a global schema.} A schema covering the union of all tools
must admit every tool's parameters, and therefore cannot reject an argument
object that is valid for a different tool. A per-recipient schema rejects it.
CSCD is thus strictly more precise than whole-completion constraint, not merely
cheaper.

\textbf{Cost.} CSCD introduces additional server round trips per invocation. With
prefix caching the recomputation is bounded by the tokens generated after the
phase boundary. We report the measured overhead as \PH{F}~ms per call and
\PH{G}\% per task.

\section{Dispatch Surface and Containment}
\label{sec:surface}

\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth]{figures/fig3-dispatch.png}
\caption{The dispatch surface. (a) With tolerant parsing and prose-level call
recovery, untrusted repository content transitively reaches the tool dispatcher
and then an ungated shell. (b) Channel-scoped constrained decoding removes the
need for prose-level dispatch, and the capability profile confines execution; the
path is broken at two independent points.}
\label{fig:dispatch}
\end{figure}

\subsection{Definition and growth}

Let the \emph{dispatch surface} $D(A)$ of an agent $A$ be the set of text regions
from which the orchestrator of $A$ can derive a tool invocation. For the
configurations we study,
\begin{align}
D_{\text{strict}} &= \{\text{well-formed call headers in model output}\},\\
D_{\text{salvage}} &= \{\text{header-like spans in model output}\},\\
D_{\text{prose}} &= \{\text{all prose the model emits}\}.
\end{align}
The third case is the consequential one. An agent that reads a file commonly
restates its contents while reasoning, so
$D_{\text{prose}} \supseteq \{\text{repository contents}\} \cup
\{\text{command output}\}$, both attacker-controlled. Fig.~\ref{fig:dispatch}(a)
traces the resulting path: untrusted content enters the context as a tool result,
is restated in reasoning, is recovered as an invocation, and reaches a shell.

\subsection{Containment}

We compile the permission mode into a capability profile
$(\textit{fs}_{r}, \textit{fs}_{w}, \textit{net}, \textit{exec})$ and enforce it
below the agent process using unprivileged user namespaces: read-only bind mounts
outside the project root, read-write within it, an unshared network namespace,
and termination with the parent. Two consequences follow. First, the execution
tier is brought inside the same boundary as the write tier, which it previously
bypassed. Second, the absence of network egress becomes an enforced property of
the deployment rather than an assumption about its environment, which is what the
privacy claim of this work requires.

Fig.~\ref{fig:dispatch}(b) shows the result. The path is severed at two
independent points: CSCD removes the need for prose-level dispatch, and the
profile confines execution. Independence matters, because the security claim then
does not rest on the decoding contribution alone.

\section{Evaluation Design}
\label{sec:eval}

\textbf{Platform.} gpt-oss-20b in its native MXFP4 format, served by a single-slot
local server on one \PH{GPU model, VRAM} with a \PH{ctx}-token context. Sampling
is fixed and reported; the seed is logged per trial; dependencies are pinned by
exact version, including the Harmony renderer, whose version determines the
prompt bytes.

\textbf{Suites.} (i) A repository question-answering suite of \PH{Q} questions
over \PH{R} open-source repositories, each answer annotated with the file and
line ranges that must be consulted, which makes grounding verifiable without a
judge model. (ii) An issue-resolution subset of \PH{S} instances scored by the
repositories' own tests. (iii) An injection suite of \PH{N} scenarios across four
untrusted channels and five payload classes, each with a machine-checkable oracle.

\textbf{Arms.} Decoding is varied over \{unconstrained, unconstrained with
repair, whole-completion schema, CSCD\}; containment over \{none, deny-list,
enforced\} crossed with repair over \{off, salvage, prose-level\}.

\textbf{Baselines.} The same weights driven by the server's native tool-call
templating; one established open agent harness on the same weights; and a larger
open-weight model as a capability ceiling, labelled as such rather than as a
competitor.

\textbf{Protocol.} Five seeds per cell. We report reliability@5, the fraction of
seeds succeeding, alongside means with 95\% confidence intervals, because single
observations from a stochastic loop are not results.

\textbf{Grounding.} An append-only evidence ledger records
$(\textit{obs\_id}, \textit{tool}, \textit{path}, \textit{lines},
\textit{hash})$ for each observation, is excluded from compaction, and is cited
by the final answer; a checker re-reads each cited range and verifies the hash.
Grounding is therefore established mechanically, which is necessary here because
a judge model would either require a hosted service, contradicting the offline
premise, or the model under test, which is circular.

\section{Threats to Validity}

\textbf{Construct.} Our grounding metric verifies that cited line ranges contain
what was observed; it does not verify that the answer follows from them. We
therefore report it as grounding, not as correctness.

\textbf{Internal.} Numerical non-determinism in batched inference is a known
confound~\cite{nondeterminism2025}; we mitigate it with a single server slot, a
logged seed, and reliability@$k$ rather than single-run reporting.

\textbf{External.} Results are obtained with one model on \PH{R} repositories in
\PH{L} languages, and the dispatch-surface argument is formulated for a
channel-structured response format. Generalisation to other formats requires an
analogous separation between reasoning and invocation regions, which we expect
but do not demonstrate.

\textbf{Conclusion.} The security result depends on an injection suite we
constructed, which cannot be exhaustive; it establishes a lower bound on attack
success, not an upper bound on safety.

\section{Conclusion}

Repairing a weak model's malformed tool calls and securing the agent that runs
them are not independent objectives. We showed that prose-level call recovery, a
mechanism adopted to improve task success, extends the dispatch surface until
untrusted repository content can reach tool execution, and that the structural
failures motivating such recovery can instead be eliminated at decode time by
constraining only the machine-parsed regions of a channel-structured completion.
Combined with a capability profile that enforces the permission model below the
agent process, this yields an agent that is reliable and contained while
remaining entirely offline. Future work includes extending channel-scoped
constraint to formats without explicit channel markers, and quantifying the
residual semantic error that no structural guarantee addresses.
